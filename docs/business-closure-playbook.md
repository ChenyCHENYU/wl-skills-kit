# 业务页面生成防漏闭环

本手册把真实项目中反复暴露的缺陷收敛为生成前契约、实现门禁和验收证据。目标不是记住某个炼钢页面，而是让任何业务模块都不再依赖对话记忆补齐关键规则。

## 一、生成前必须结构化的事实

以下信息不得只写在 `notes` 或聊天记录中；存在时写入 `page-spec.features.acceptance`：

| 业务事实 | 契约位置 | 最低声明 |
| --- | --- | --- |
| 炉号/批次号上下键 | `queryControls[kind=step-navigation]` | 字段、必须先有值、来源 |
| 查询默认日期 | `queryControls[kind=default-date-range]` | 起止字段、相对天数、来源 |
| 长文本完整显示 | `queryControls[kind=full-value-display]` | 字段、tooltip/auto-width/full-width |
| 新增/修改去重 | `uniqueness[]` | 真正业务字段、create/update、有效数据、归一化、业务提示 |
| 合并/统合/批处理 | `batchOperations[]` | `selected-only`、最少数量、一致字段、恰好 N 个分组 |
| 验收上下文 | `verification` | company/tenant、正向/无命中/重置、同租户写后读 |

技术字段名或历史索引不能替代业务口径。例如需求说“整备项目去重”，不得把项目号一并加入；需求说“所选计划统合”，不得扫描并校验同浇次所有未选记录。

## 二、跨层一致性清单

1. 查询项必须同时存在于 page-spec、页面控件、请求 DTO、Mapper/接口参数和验收用例；只改标签不算补齐查询。
2. 必填项必须同时覆盖新增和修改；字段长度同时对齐前端约束、API 契约、后端 DTO、数据库容量和业务文档。
3. 分页可选值不得超过 Delivery Profile 的 `maxSize`；新增 `999条/页` 等选项前先改统一口径并做边界测试。
4. 软删值、租户来源和公司别是项目事实。写后读测试必须使用同一 company/tenant；缺公司上下文应判为测试前置失败，不得上报“写入成功但查询不可见”。
5. 错误提示使用业务对象名称，例如“料号已存在，请勿重复添加”；禁止展示“业务唯一键”“constraint”“duplicate key”。
6. 无需调整、无数据等可恢复状态使用 warning/info；真正失败才用 error。涉及两条记录时，提示应包含来源与目标的序号和业务编号。

## 三、最低验收矩阵

- 查询：精确/模糊正向命中、无命中、重置恢复、分页最大值。
- 新增/修改：必填为空、边界长度、同键冲突、修改自身不误判、软删后重建策略。
- 批量：正向、少选、跨多组、不一致字段、已下达/已生产等状态拒绝；所有负向均证明零写入。
- 交互：上下键边界、默认日期、长文本完整可见、提示严重级别及来源/目标文案。
- 身份：登录有效、company/tenant 非空、权限存在；写后用同租户回读。
- 清理：优先业务 API；无回撤 API 时仅允许带精确条件、事务和前后断言的受控清理。

## 四、发布闭环

前端构建、接口冒烟和数据库只读复核必须绑定同一提交。Spring Boot 制品等非确定性产物的源码提交不能替代实际部署文件哈希；交付记录应冻结实际上传制品。需要数据库变更时，内外网交接一次性给出文件哈希、环境门禁、停止条件、pre/post SQL、备份恢复和冒烟清单，避免边执行边补问题。
