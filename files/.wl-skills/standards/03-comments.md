# 03 — 注释规范

注释使用中文，API 名、类型和技术术语保留原文。优先解释业务职责、契约来源、处理顺序、特殊边界及兼容原因，让读者快速理解代码。

- 为关键业务流程和不直观的共享入口添加简短注释；简单赋值、明显的函数名无需逐行复述。
- 普通说明使用 `//`，公共接口和函数契约可用 `/** ... */`。两种写法均有效，不因注释格式阻断。
- 文件头插件可选，不要求安装特定编辑器插件，也不创建无意义的模板注释。
- 删除注释掉的死代码、过时说明和无效 TODO；历史通过 Git 查询。
- 临时 TODO 说明具体未决事项与责任人或日期，不写“待优化”等空泛内容。

## 新生成和重构代码必须说明的边界

| 位置 | 注释必须解释的内容 |
| --- | --- |
| 页面或共享组合函数入口 | 负责的业务流程、状态的实例边界；一句即可 |
| 提交、删除、审批等关键动作 | 载荷来源、执行顺序及失败后为何保留或清理状态 |
| 多字段联动、计算和回填 | 哪个字段是来源、何时覆盖、何时保留人工修改 |
| 非直观校验和单位转换 | 已确认的业务/接口契约、相等和空值等特殊边界 |
| Vue 宿主、平台组件兼容入口 | 实际运行版本或缺失能力、兼容原因及处理范围 |
| 私有样式兼容 | 对应的原布局差异；共用修复应进入组件或模块样式 |

生成时主动添加这些说明，不能等使用者逐项提醒。不得给每个字段、getter 或显然的
函数套空泛注释，也不能仅按函数名猜测业务规则。注释只能描述已实现、已确认的行为。
已有有效代码不因缺少某种注释格式报错；质量检查继续聚焦真实错误、死代码及复杂度。

```typescript
// 保留勾选先后顺序，表格返回的行顺序不能代表用户指定的计划顺序。
const requestedIds = selectionClickOrder.value;
```


## 文件头职责说明（K22，结构检查）

新增或本次重构的前端业务文件（index.vue / data.ts / index.scss / 共享组合函数）必须有简短且真实的职责说明：

- 页面文件说明其归属模块、菜单/页面路径（事实来源：已确认菜单或路由配置、api.md 契约头、需求文档）与文件角色。Vue 是视图绑定，data.ts 是业务状态/接口/事件，样式是该页布局及兼容范围。
- `@Description` 禁止保留占位模板（“这是默认设置”“请设置 customMade”“打开 koroFileHeader 查看配置”等）；K22 对占位模板报 warn，对“有注释头但缺职责说明”报 info 建议。
- 已有 Author/Date/LastEditors/LastEditTime/FilePath 等字段原样保留，按项目编辑器配置维护；通用包模板不硬编码个人信息，不强制安装文件头插件，不伪造作者或历史时间。
- 没有完整菜单路径事实时，写已确认的页面/文件职责并注明路径未确认；不得从目录英文名猜测菜单。
- 菜单事实变更后，仅更新确认失效的说明；不改写其余头部字段与正文。

结构检查只能证明“说明存在且无占位内容”；说明是否与业务实现一致，需结合 api.md/菜单配置等事实来源在评审中人工确认（工具不宣称语义正确）。

### 分发与检查边界（v2.27.0）

前端规则由 kit 单包提供；无需 UI 或 harness。page-codegen、code-fix、convention-audit 执行前引用本规范，在新建/本次修改的文件中落实职责说明和必要的“为什么”。保留未涉及的历史内容，不全库补注释。

K22 只扫描页面目录的 index.vue/data.ts/index.scss 开头的真实注释，识别空职责/插件占位、元数据缺说明；接受普通职责注释。无头存量文件不新增默认阻断。代码生成器对 codegen/runtime 的 Vue/TS/SCSS 统一加职责头；检查结构通过不代表业务说明准确，也不证明模型已经加载规则。
